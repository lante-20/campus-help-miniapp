# 校园互助小程序 · 本机演示版

当前无需租用服务器，也无需开通云环境。默认配置为 `config.js` 中的 `mode: 'local'`。

这是本机功能演示，不是可供多人在线使用的版本：任务、账号、消息、草稿和举报保存在同一台设备；切换演示账号可以模拟双方操作。不要填写真实的取件码、门牌、手机号等信息。

## 运行

1. 在微信开发者工具中导入本目录。
2. AppID 使用你有开发权限的小程序 AppID；仓库里的原始 AppID 不代表你拥有它的开发权限。
3. 编译后输入昵称及演示账号，例如 `studentA`。头像选填，不调用 `wx.login`、手机号授权或云数据库。
4. 发布一条未来截止的跑腿任务，或填写完整物品描述及发生时间的失物招领。
5. 在“我的”切换为 `studentB`，接取任务并发送消息。
6. 切回 `studentA`，进入“消息”回复，在任务详情确认完成。
7. 双方均可从“我发布的 / 我接的”进入历史详情；已完成任务不能重新接取。举报记录在“我的 → 本机举报记录”查看。

清除小程序本地数据将丢失这些记录。账号输入相同名称即可再次进入，因此它不具备真实登录的安全性。

## 这次改动

- 本地集合支持直接排序、嵌套字段查询、OR 条件、分页及明确的存储错误。
- 查询和写入都返回 Promise；不存在的记录不再假装更新成功。
- 接单与结束操作集中在 `utils/task-service.js`：检查本机身份、发布者、状态及截止时间，并在同一 JS 上下文内检查状态后同步写入。
- 并发点击接取同一任务只允许一次成功。这个保证仅针对当前本机模拟，不是多设备或云端事务。
- 跑腿和失物招领使用不同表单；金额最多两位小数，跑腿截止时间必须晚于现在。
- 草稿按演示账号隔离，离开页面或手动保存时写入；成功发布后清空。
- 首页按类型筛选后分页；个人任务与消息列表提供分页和详情入口。
- 聊天初始显示最近 30 条，可加载更多；只查询任务双方的消息，页面隐藏后停止刷新；没有变化时不重新下发整份消息列表。
- 公开卡片不展示地址和账号，任务双方可在详情查看地址 / 取件码。本机存储不提供安全隔离，不应承载真实敏感数据。
- 清理未引用、重复的 CloudBase Web SDK，保留原生小程序结构。
- 举报页明确标为本机演示，不宣称已向真实管理员提交。

## 自动检查

在仓库根目录（本目录的上一级）执行，要求 Node.js 18 或更高版本，不需要安装 npm 依赖：

```powershell
npm test
npm run check
```

测试模拟微信 API，覆盖任务闭环、双人接单竞争、非参与者访问、数据失败、表单规则、列表筛选、草稿隔离和聊天生命周期。检查脚本校验 JS / JSON、页面文件、相对模块依赖和静态事件绑定，不替代微信开发者工具的 WXML / WXSS 编译。

## 云端尚未接入

`cloudfunctions/` 保留的是原仓库的旧示例，不参与本地演示，也**不应直接部署后当成正式版本**。尤其旧 `acceptTask` 未具备完整的可信身份、权限及并发接单保护。

`mode` 设置为非 `local` 会明确报错，不会悄悄退回本地存储。当前没有可直接开启的云端开关。

将来可使用微信云开发，不必自行租用和维护服务器。接入时需要：

- 开通云环境，初始化原生 `wx.cloud`，实现真正的数据适配层。
- 服务端用 `cloud.getWXContext().OPENID` 获取可信身份；演示账号不能作为权限依据。
- 用服务端事务 / 条件更新实现唯一接单，校验所有任务状态变更。
- 为用户、任务、消息、举报配置数据访问权限；单独建立管理员身份及处理流程。
- 补齐内容审核、文件持久化、索引及多设备测试，再准备正式发布。
- 单独设计本地旧数据迁移，不能将手填的演示账号直接视为真实用户。

费用和配额以云服务实际开通方案为准。
